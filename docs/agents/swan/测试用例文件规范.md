### ⚠️ 测试用例文件规范 (强制遵守)

1. **一个用例一个文件**: 每个测试用例必须单独存在一个.py文件中，不要把多个用例放在同一个文件
2. **固定方法名**: 每个用例文件中必须有 `setup()` 和 `teardown()` 方法，**必须使用这两个名字**，不要改成 `setup_method` 或其他名字
3. **禁止Page模式**: 本工程**不使用Page Object模式**管理页面，通过在用例中使用 `userA.createTeam()` 这样的方法完成对应的业务流程
4. **登录/退登由框架自动管理**: 登录和退登在 Session 级别自动执行，**用例中不需要手动调用 login() / logout()**
5. **POPO 启停由框架自动管理**: 框架在每个用例 setup 前自动调用 `open_app()` 打开 POPO，teardown 后自动调用 `close_app()` 关闭 POPO
6. **用户实例化位置**:
   - `setup()` 方法中：用户实例化 `self.userA = self.users("userA")`（无需 login）
   - `teardown()` 方法中：自定义清理逻辑（无需 logout）
