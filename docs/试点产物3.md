【v2 暴露的 4 个新硬伤】
================================================================

硬伤 1：Stage 3 拼 prompt 用了不存在的类名，LLM 又凭空编
  - page_message_chat.draft.json 用了 page_class = MessageChatFragment（不存在）
  - page_recent_message.draft.json 用了 page_class = RecentMessageFragment（不存在）
  - 真实类名是 MessageActivity / RecentMessageFragment2
  - 后果：elements_raw.jsonl 匹配返回 0 条 → LLM 拿不到原始元素 → 又开始凭空编 8 / 7 个元素
  - 这跟 v1 PublishActivity 编 9 个元素是同源 bug，没根治。
  - 修复方法：Stage 3 拼 prompt 前必须用 page_id_suggestion 反查 stage1_entities_raw.jsonl
    拿到真实 class_name，再用真实 class_name 查 elements_raw。如果 elements_raw
    返回 0 条，必须停下报警告"该实体在 elements_raw 中无元素"，不允许 LLM 凭空写元素。

硬伤 2：Stage 4 渲染严重欠缺（修正 4 没做到位）
  - 5 份 draft 在 pilot_v2/drafts/，但 pilot_v2/pages/ 只有 2 份 md
  - 缺：message_chat / recent_message / user_detail
  - 必须把 5 份 draft 全部渲染成 md，缺一不可。

硬伤 3：md 文件名中文部分还是 GBK 乱码（修正 5 没做到位）
  - 现状：group_manage_dialog_鍒嗙粍绠＄悊寮圭獥.md
  - 期望：group_manage_dialog__分组管理弹窗.md
  - 根因：写文件时 OS API 用了 GBK，没强制 UTF-8。
  - 修复方法：用 Python 写文件统一加 encoding='utf-8'。Windows 上文件名本身需要
    Path 用 unicode 字符串而不是 bytes。如果还不行就只用 page_id 英文部分作为
    文件名：group_manage_dialog.md（中文名只放在 frontmatter 里）。

硬伤 4：HomeActivity 的 layout 引用前后矛盾
  - stage1_entities_raw.jsonl 写：layout_xml = R.layout.activity_drawer_home_layout
  - home.md frontmatter 写：layout dialog_new_tab_nav_guide
  - 两边对不上，LLM 自己改了 layout 名。
  - 修复方法：Stage 3 prompt 里只提供 stage1 中的 layout_xml 字段，不允许 LLM
    自己改写 layout 名。layout 名是机械事实，不是 LLM 判断范围。

【设计决策需求 - 元素聚合策略】
================================================================

v2 中观察到 LLM 在 draft 里做了元素聚合（74 个原始 view → 8 个语义元素）：
  - HomeActivity: elements_raw 74 个 → draft 8 个
  - UserDetailActivity: elements_raw 102 个 → draft 几个
  - PublishActivity: elements_raw 63 个 → draft 多少个待查

聚合本身合理（真机校准不需要 74 个独立 view），但聚合规则没记录，
有 LLM 失控的风险（漏掉关键 view 不可审计）。

策略要求：保留聚合，但每个聚合元素必须列出 "raw_view_ids" 字段，
列出来自哪些 R.id。这样既好用又能审计。

draft.json 中的 element 增加字段：
  {
    "name_zh": "标题栏(含会话名称+更多按钮)",
    "raw_view_ids": ["title_root", "title_text", "btn_more", "btn_back"],
    ...
  }

最终 md 中元素表格新增"原始 view"列。
