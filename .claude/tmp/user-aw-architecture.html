User 与 AW 分层架构

User 只做组合入口，不含任何操作方法；AW 按端分基础层、按项目分业务层， 公共引擎 AWBase 全项目只维护一份。下面三张图说清继承、组合与一条调用的完整路径。

全景：组合与继承

左轴是层级，三列是平台（web / flutter / android）。实线是持有与调用，朱红虚线是继承。

Swan 的继承链（MRO）

每一层贡献什么方法，一次看清。方法查找沿这条链从左到右进行。

一条调用怎么走

以 userA.login_by_sms(userA.phone) 为例（flutter 列）：

  1. User 实例上找不到 login_by_sms，常规属性查找失败，触发 User.__getattr__（utils/user.py:55）
  2. getattr(self.business, name) —— 转发给 self.business，即 SwanBusiness 实例
  3. SwanBusiness.login_by_sms 项目业务方法执行，内部调用 self.click_image("登录_按钮")
  4. 按 MRO 查找 click_image：SwanBusiness → CommonBusinessMixin → FlutterBaseAW → AndroidBaseAW → AWBase 命中（截图 + 模板匹配）
  5. AWBase 经 self.driver 调 FlutterAndroidDriver，操作落到真机
userA = users("userA")               # conftest 工厂：按名缓存，账号走环境变量

userA.login_by_sms(userA.phone)      # ① __getattr__ 代理 → business
userA.biz.login_by_sms(...)          # ② biz —— business 的短别名
userA.aw.click_image("登录_按钮")    # ③ aw —— 就是同一个 business 实例

# 三种写法指向同一个对象：
assert user.aw is user.biz is user.business    # True —— 业务实例继承了端 base 与公共引擎

新代码放哪

按这张表落位，两层维度就不会放错。

要加什么落点
端专属操作（accessibility、press_back）utils/aw/base/<端>_base.py
项目业务方法（login_by_sms）utils/aw/business/<项目>.py
跨项目通用业务（OTP 取码）utils/aw/business/common.py
公共引擎能力（OCR / 图像匹配）utils/aw/aw_base.py —— 唯一一份
新项目接入business/<项目>.py + User 子类绑 business_cls

不走 pytest fixture 的脚本场景可用 create_business(driver)（utils/aw/business/__init__.py:39）—— 按 driver.platform_name 自动选择业务类；用例内则统一经 conftest 的 users fixture 获取用户。
