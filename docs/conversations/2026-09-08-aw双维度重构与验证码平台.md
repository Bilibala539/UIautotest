## 一、验证码平台（swan-otp-gateway）

### 背景
Flutter App（Swan，`com.swan.network`）UI 自动化登录需要短信验证码。虚假手机号收不到真实短信，与开发协商落地了一个内网验证码平台。

### 演进决策（与开发多轮协商的结果）
1. 初始：开发在服务端生成验证码后、调短信服务商前，主动 POST 推送到平台（push 模式）。
2. 简化：接口只传 `phone` + `code`；随后按内网公开使用的要求，全部接口免鉴权。
3. 展示：手机号完整显示（不脱敏）；历史记录永久保留（available/expired/consumed），不自动清理。
4. **最终（当前）pull 模式**：开发提供查询接口，平台收到 `latest?phone` 请求时**主动**去调开发接口取码。

### 线上部署状态
- 服务：`swan-otp-gateway.service`（systemd，开机自启，非 root 运行）
- 机器：`192.168.12.5`（Proxmox LXC，Ubuntu，同机还有 Jenkins 等其他平台，故用 Swan 专属路径）
- 地址：`http://192.168.12.5:18080`；数据 `/var/lib/swan-otp-gateway`（SQLite）
- 本地代码：`scripts/otp_gateway/`（server.py / README.md / systemd 文件），测试 `tests/flutter/test_otp_gateway.py`

### 接口（全部免鉴权）
- 自动化读取：`GET /api/test/otp/latest?phone=…`（pull 入口，404 可轮询）
- 开发取码源：`GET <测试服>/user/captcha/mockCode?tel=…`（平台主动调用，支持纯文本/`mockCode`/`data.mockCode`）
- 列表：`GET /api/test/otp/recent?limit=200`；消费：`POST /api/test/otp/consume`（`{"id":1}`）
- 网页：`http://192.168.12.5:18080/`

### 未决
- 开发给的域名 `testnetwork.hivi.com` DNS 可达但 `/user/captcha/mockCode` 返回 404，完整 URL 未定；虚拟机配置 `CAPTCHA_SOURCE_URL` 目前为空。
- 开发测试服在阿里云，与办公内网默认不通（虚拟机只有 fe80:: 链路本地 IPv6）；备选：VPN / 部署到阿里云同 VPC / FRP。

## 二、本项目框架改造（utils/aw 双维度重构）

### 决策过程
1. 确认取验证码逻辑封装为「HTTP 客户端 + 业务层方法」，不进 aw_base（设备交互唯一入口）、不出现在用例里 → `utils/otp_client.py`。
2. 目录形态讨论：确定「先按层（base/business），再分端」的方案 A，否定「先分端再分层」。
3. 用户类按项目拆分：`User` 基类 + `TTUser`/`SwanUser`；业务方法经 `__getattr__` 代理，user 类不写业务实现。
4. **最终双维度模型（用户拍板）**：
   - 基础 AW **按端分**，每端一套操作方法（web/android/flutter）
   - 业务 AW **按项目分**，每项目一套（TidiTree / 安卓项目 / Swan）
   - 一个端可挂多个项目（web 端现在是 TidiTree，以后会有别的平台）
   - TidiTree 只有 web 端；android 端是**另一个独立项目：智能音箱显示屏系统（正式名待定）**

### 当前结构（已落地）
```
utils/
├── otp_client.py            # OtpClient：轮询 latest、consume；地址走 SWAN_OTP_GATEWAY
├── user.py                  # User 基类 + TTUser/AndroidUser/SwanUser（__getattr__ 代理）
└── aw/
    ├── aw_base.py           # 公共引擎（一份）：OCR/截图/图像匹配
    ├── base/                # 基础 AW 按端分
    │   ├── web_base.py      # WebBaseAW（web 端新操作放这里）
    │   ├── android_base.py  # AndroidBaseAW：press_key/press_back/press_home
    │   └── flutter_base.py  # FlutterBaseAW(AndroidBaseAW)：accessibility_exists/click_accessibility
    └── business/            # 业务 AW 按项目分
        ├── common.py        # CommonBusinessMixin：otp/wait_text/_fetch_sms_code/login 骨架
        ├── tiditree.py      # TidiTreeBusiness(CommonBusinessMixin, WebBaseAW)
        ├── android.py       # AndroidBusiness（智能音箱屏项目，名称待定，定名后全局重命名）
        └── swan.py          # SwanBusiness：login_with_password / login_by_sms
```
- MRO：`SwanBusiness → CommonBusinessMixin → FlutterBaseAW → AndroidBaseAW → AWBase`
- `user.aw` 即业务实例（业务类继承了端 base），基础操作与业务方法都能从 userA 直接调
- conftest 按 `PLATFORM` 分发用户类：web→TTUser、android→AndroidUser、flutter→SwanUser
- 跨项目调用 fail fast（AttributeError）
- 端专属方法已从 AWBase 物理下沉（press_*→android_base，accessibility_*→flutter_base），
  `explore_flow` 的 back 步骤做了无 press_back 环境的兼容；遗留脚本 `scripts/swan_login_logout_opencv_ocr.py`
  已改用 FlutterBaseAW。
