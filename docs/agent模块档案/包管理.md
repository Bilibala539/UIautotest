> 维护者：包管理 agent。更新日期 2026-09-20。供 teammate 会话拉起时快速恢复上下文；行号锚点格式 `文件:行号`，改码后须同步更新。

## 1. 一句话职责
APK 产物的登记与台账：以 `apk_id` 为主键登记包元数据（版本/分支/commit/sha256），供执行会话（runs.apk_id）与流水线任务（pipeline_jobs.apk_id）按包关联与过滤执行结果。

## 2. 数据表
### apks（DDL `dashboard/server.py:485-504`，存量迁移 `server.py:505-521`）
| 字段 | 类型 | 说明 |
|---|---|---|
| apk_id | TEXT PK | 格式 `swan-<branch>-<shortsha7>-<yyyymmdd>`（与 build_swan_apk.py 一致） |
| app_version / branch / commit_hash / flavor / notes | TEXT 默认'' | 元数据，登记时可全空 |
| source | TEXT 默认 manual | manual / pipeline / dev / auto-build |
| server_type | TEXT 默认 test | formal=正式服 / test=测试服（`VALID_SERVER_TYPES` `server.py:58`；存量库 ALTER 后默认 test） |
| build_time | TEXT 可空 | 构建时间（ISO），POST /api/apks 接受 |
| jenkins_job / jenkins_build | TEXT 默认'' | 触发该包构建的 Jenkins job 名与 build 号（2026-09-20 加列，轻量迁移 `server.py:513-521`）；build_swan_apk.py 登记时带 JOB_NAME/BUILD_NUMBER env（`build_swan_apk.py:316-317`）；服务端据此拼 jenkins_log_url |
| file_path / file_hash | TEXT 默认'' | 本地产物路径 + sha256（脚本侧填，页面手登为空；下载接口按 file_path 回源） |
| registered_at | TEXT NOT NULL | upsert 时不更新 → 恒为首登时间 |

## 3. API 路由清单
| 方法 | 路径 | 用途 | 锚点 |
|---|---|---|---|
| GET | /api/apks?limit=N&server_type= | 列表，registered_at DESC，limit 1-200 默认 50；server_type 过滤（formal/test，非法值忽略）；每行附 download_url（按请求 Host 的绝对地址）、file_exists、jenkins_log_url（服务端拼 `{JENKINS_PUBLIC_URL|JENKINS_BASE_URL}/job/{job}/{build}/console`——优先 PUBLIC_URL（对外可达，浏览器跳转用），未配置回退 BASE_URL（服务端回调用，可为 localhost）；env 每请求实时读，基址未配置或包无构建号→空串，前端空串不渲染日志按钮） | `server.py:2204-2226` |
| GET | /api/apks/<id>/download | 按 file_path 回源 APK 文件流（1MB 分块），Content-Type=application/vnd.android.package-archive，Content-Disposition 用 apk_id.apk 命名；包不存在 404，文件不在磁盘 404+明确错误 JSON（提示补登） | `server.py:2229` 起 |
| POST | /api/apks | 登记（upsert），201 Created；apk_id 缺失 400；server_type 非法 400；接受 build_time 与可选 jenkins_job/jenkins_build | `server.py:2466-2468` |
| DELETE | /api/apks/<id> | 删除台账行（**只删 apks 行**，磁盘文件与 runs 执行历史不动）；不存在 404 | `server.py:2657` 起（do_DELETE `server.py:2654`），store `delete_apk` `server.py:1380-1388` |
| POST | /api/builds | 主动触发 Jenkins 打包（打包构建模块所有，本模块仅前端消费）：branch 必填 400 / server_type 非法 400 / notes>200 400 / Jenkins 未配置 503 / 触发失败 502；成功返回 {ok,job,queue_id,location}，location 为队列地址 | `server.py:2469` 起 |
| GET | /api/runs?platform=&apk_id=&limit= | 执行会话按包过滤 | `server.py:1836-1848` 附近 |

Store 层：`register_apk` `server.py:1310-1358`（jenkins_job/jenkins_build 空回退 ''）（apk_id 必填；server_type 必为 formal/test 默认 test；build_time 空存 NULL；ON CONFLICT(apk_id) DO UPDATE 全量覆盖含 server_type/build_time，registered_at 保留首登）、`get_apk` `server.py:1360-1365`（KeyError→404）、`list_apks(server_type=)` `server.py:1367-1378`、`delete_apk` `server.py:1380-1388`、`list_runs(apk_id=)`。run 上报带 apk_id 走 `create_run`。下载辅助：`apk_file_on_disk` `server.py:65-68`、`base_url()`（按 Host 头生成绝对基座，GET /api/apks 内调用 `server.py:2213`）。

## 5. 脚本与守护进程
### scripts/register_apk.py（手动登记入口，无守护进程）
- 用法：`python scripts/register_apk.py <apk路径> [--version --branch --flavor --commit --apk-id --source --server-type]`
- 逻辑：整文件读入算 sha256（`register_apk.py:45`）；apk_id 自动生成 `swan-<branch|manual>-<commit前7位|hash前7位>-<yyyymmdd>`（`register_apk.py:46-48`），POST /api/apks；`--server-type` choices formal/test 默认 test（`register_apk.py:34-36`，与 build_swan_apk.py 同口径）；目标平台读 `DASHBOARD_URL` 环境变量，默认 `http://192.168.12.166:8080`（`register_apk.py:21`）
- 已知坑"apk_id 必填缺了报错"的修复情况：**脚本侧已修复**——apk_id 恒自动生成，分支空回退 'manual' 防空段（`register_apk.py:47-48`）；也可 `--apk-id` 手动指定。服务端必填校验是唯一兜底（`server.py:1300-1305`，apk_id/server_type）；**页面无登记入口**（2026-09-20 合并页移除登记弹窗，登记对用户无感）。

## 6. 关键业务规则与坑
1. **apk_id 是唯一 upsert 键**：同 ID 重复登记=覆盖元数据（registered_at 保留首登值，UPDATE 列表里没有它）。**删除 API 已有**（DELETE /api/apks/<id>）：只删台账行，磁盘文件与 runs/pipeline_jobs 里的 apk_id 文本不动（弱关联历史仍可读）；无编辑 API。
2. **弱关联无校验**：runs.apk_id、pipeline_jobs.apk_id 均为自由文本，登记/删除均不校验、无外键；用例历史三视角联查直接取 runs.apk_id。
3. **执行次数列已移除**（2026-09-20 用户拍板）：原客户端近似统计（>200 条 runs 失真）连 `dlExecCounts` 一起删除，loadApks 不再请求 /api/runs；按包看执行走执行会话页 apk_id 筛选下拉。如需恢复建议服务端 COUNT 聚合。
4. **页面改动须重启服务**：DASHBOARD_HTML 启动时整体读入，热改 page.html 不生效。
5. **limit 上限 200**：apks/runs 列表均 clamp 到 1-200。
6. Windows GBK 控制台中文/emoji 输出乱码或 UnicodeEncodeError 是显示问题，不影响实际数据；脚本已 `stdout.reconfigure(utf-8)`（`register_apk.py:34-35`），冒烟脚本同样要加。
7. **server_type 校验在服务端**：非 formal/test 直接 400，前端胶囊/服别下拉只发这两个值；列表过滤对非法值静默忽略（对齐 list_runs 对 platform 的处理）。
8. **下载依赖登记机磁盘**：download 接口按 file_path 回源，file_path 是登记机本地路径——跨机下载仅在登记机本机/路径可达时可用；文件缺失返回 404+提示，前端用 file_exists 禁用按钮。
9. **主动打包异步性**：POST /api/builds 成功只代表进 Jenkins 队列（返回 location=队列地址），包不会立刻出现在列表；前端不刷列表，构建完成由 build_swan_apk.py 自动登记（APK_ID 口径）后刷新可见。notes 走后端 quote 编码传 Jenkins（规避 Windows 批处理编码坑），前端传明文 JSON。
10. **jenkins_log_url 是服务端拼装**：基址优先读 env `JENKINS_PUBLIC_URL`（对外可达地址，浏览器用），未配置回退 `JENKINS_BASE_URL`（服务端回调用，可为 127.0.0.1——实测 .166 配 localhost 打不到日志页的坑，2026-09-20）；每请求实时读，改 env 无需重启服务，job/build 段 quote 转义；三要素缺一返回空串、前端不渲染按钮。app_version 列目前恒为 '-'（App 侧未提供版本号，列保留待接）。
