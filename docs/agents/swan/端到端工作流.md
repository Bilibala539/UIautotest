# Swan 端到端工作流（需求 → 可运行用例）

> 本文件定义 Swan 项目单功能从**接到需求**到**交付可运行测试用例**的完整工作流（Phase 1-5）。
> 自 `.claude/rules/ai_workflow.mdc` 并入（2026-10-14 清理，路径已全部 Swan 化）。
> 多 agent 派发视角（模式判断/门禁/回退）见 `aw-orchestrator.md`；本文是用例作者的执行视角。

## 执行形态

### 全自动（默认）

用户说 **"按照工作流"、"端到端覆盖 XX"** 时：
1. 一口气走完 Phase 1~5，中间不停顿等确认
2. 每个 Phase 内部遇到问题自主决策解决，不中断询问
3. Phase 5 失败自主排查修复并重跑，最多 3 轮
4. 全部完成后统一输出交付报告（见下方模板）

### 分步

用户只提某个阶段（"探索 XX 页面"、"截按钮"、"写 XX 的 AW"、"跑测试"）时：只执行对应 Phase（Phase 1 加载知识库仍不可跳过），完成后汇报并等待下一步。

| 用户说的话 | 模式 | 执行范围 |
|-----------|---------|---------|
| "按照工作流实现 XX" | 全自动 | Phase 1~5 |
| "探索一下 XX 页面" | 分步 | Phase 1~2 |
| "截取 XX 页面的按钮" | 分步 | Phase 1 + 3 |
| "帮我写 XX 的 AW" | 分步 | Phase 1 + 4 |
| "运行测试" | 分步 | Phase 1 + 5 |

## 工作流全景

```
用户提出需求
    │
    ▼
Phase 1: 加载知识库 + 确定目标（aw-explorer）
    │
    ▼
Phase 2: 探索 App 页面（aw-explorer）
    │
    ▼
Phase 3: 截取 UI 元素图片（aw-element）
    │
    ▼
Phase 4: 生成 AW 代码 + 测试用例（aw-codegen）
    │
    ▼
Phase 5: 运行验证 + 自检修复 + 图片转正（aw-verify）
    │
    ▼
交付完成（全自动模式：输出交付报告）
```

各 Phase 的派发门禁（G1-G5）与上下文注入见 `aw-orchestrator.md`。

---

## Phase 1: 加载知识库 + 确定目标

执行者：aw-explorer（蓝图 `aw-explorer.md`）

| 步骤 | 操作 | 完成条件 |
|------|------|---------|
| 1.1 | 读取 `knowledge/swan/app_map.json` | 已了解现有页面与跳转 |
| 1.2 | 对照 `knowledge/swan/pages/*.md` 与 `docs/agents/swan/AW方法指南.md` | 已识别可复用方法、缺失页面 |
| 1.3 | 与用户确认目标功能 | 用户明确了要实现的功能 |
| 1.4 | 检查目标功能是否已有探索记录 | 判断是否需要 Phase 2 |

**跳转规则**：
- 已有完整探索记录且元素图片已截取 → 跳到 Phase 4
- 已有探索记录但缺元素图片 → 跳到 Phase 3
- 未探索过 → 进入 Phase 2

## Phase 2: 探索 App 页面

执行者：aw-explorer

| 步骤 | 操作 | 完成条件 |
|------|------|---------|
| 2.1 | 连接真机（`ANDROID_DEVICE_SERIAL`），App 启动到首页 | adb 连接成功，首页可达 |
| 2.2 | 导航到目标功能起始页面 | 截图确认到达起始页面 |
| 2.3 | 逐步操作，每步截图 + 记录 | 完整走完目标功能流程 |
| 2.4 | 记录新发现的页面、跳转、元素 | `knowledge/swan/draft/<page_id>.md`（五要素）已生成 |
| 2.5 | 更新知识库（`app_map.json` transitions 双向 + pages 转正） | 知识库已包含新发现 |

**约束**：只能使用 AWBase/FlutterBaseAW 方法与 ADB 命令，禁止 Playwright；accessibility key 仅限探索辅助，运行时禁用。

## Phase 3: 截取 UI 元素图片

执行者：aw-element（蓝图 `aw-element.md`）

| 步骤 | 操作 | 完成条件 |
|------|------|---------|
| 3.1 | 从探索截图中识别需要截取的元素 | 元素清单已列出 |
| 3.2 | 判断每个元素适合图像模板还是 OCR | 只截取图标、状态标识等适合图片匹配的元素 |
| 3.3 | 查重（`grep "关键词" image/image_name_mapping.py`）后逐个截取（紧贴、避开动态元素和阴影） | 图片已存入 `image_ai/flutter/` |
| 3.4 | 执行质量检查（不空白、不全黑/全白、无角标；灰度标准差>5、均值 5-250） | 所有图片通过质量检查 |
| 3.5 | 在 `image/image_name_mapping.py` 注册常量（flutter 平台，`image_path(..., draft=True)` 校验） | 常量已注册 |

## Phase 4: 生成 AW 代码 + 测试用例

执行者：aw-codegen（蓝图 `aw-codegen.md`）

| 步骤 | 操作 | 完成条件 |
|------|------|---------|
| 4.1 | 在 `utils/aw/business/swan.py` 的 `SwanBusiness` 中编写业务 AW 方法 | 方法已添加，无 `self.tap(x,y)` |
| 4.2 | 只调用 AWBase 方法，断言优先 `image_exists`，每方法过编写规范 §8 自检清单 | 代码符合规范 |
| 4.3 | 确认业务方法经 `User.__getattr__` 自动代理可调（`self.user.xxx()`，无需手写代理） | 用例侧调用方式已验证 |
| 4.4 | 在 `tests/flutter/test_<用例>.py` 创建用例（一用例一文件一 test 方法，规则 8 铁律；文件头 `# CASE-ID:` 标记） | 用例继承 BaseTest，setup/teardown 正确 |

**约束**：所有操作用 `click_image` / `click_text`，禁止硬编码坐标；禁止 parametrize（变体各自独立成文件）。

## Phase 5: 运行验证 + 自检修复 + 图片转正

执行者：aw-verify（蓝图 `aw-verify.md`）

| 步骤 | 操作 | 完成条件 |
|------|------|---------|
| 5.1 | 代码自检（硬编码坐标、断言方式、region、sleep） | 自检清单全部通过 |
| 5.2 | 元素图片自检（命名、动态元素、留白、分辨率） | 自检清单全部通过 |
| 5.3 | 运行 `PLATFORM=flutter pytest tests/flutter/test_xxx.py -v` | 测试运行完成 |
| 5.4a | **通过** → 图片转正（`image_ai/flutter/` → `image/flutter/`，`promote_image(...)`） | 图片已转正 |
| 5.4b | **失败** → 按优先级排查：图片质量 > AW 逻辑 > 页面状态（先查图再查码） | 回到 5.3 重新运行 |
| 5.5 | 更新知识库（`app_map.json` 页面状态）+ 新业务方法登记 `AW方法指南.md` | 知识库与指南已更新 |

## 跳步规则汇总

| 场景 | 可跳过的 Phase | 说明 |
|------|---------------|------|
| 用户说"探索 XX 功能" | Phase 3~5 | 只探索，不生成代码 |
| 目标功能已有完整探索记录和元素图片 | Phase 2~3 | 直接生成代码 |
| 已有探索记录，缺元素图片 | Phase 2 | 从截取元素开始 |
| 用户说"帮我写 XX 的 AW" | Phase 2（可能跳） | 先检查知识库是否有探索记录 |
| 用户说"运行测试"或"帮我修复" | Phase 2~4 | 直接进入验证 |

**但 Phase 1（加载知识库）永远不能跳过。**

## 交付报告模板（全自动模式完成后输出）

```markdown
# 交付报告 — [功能名称]

## 探索结果（Phase 2）
- 新发现页面: X 个
- 新发现跳转: X 条
- 探索记录: knowledge/swan/pages/<page_id>.md

## 截取元素（Phase 3）
- 新截取图片: X 张
- 图片清单: [常量名 → 文件名]

## 生成代码（Phase 4）
- AW 方法: `方法名()` → utils/aw/business/swan.py（SwanBusiness）
- 测试用例: tests/flutter/test_<用例>.py

## 验证结果（Phase 5）
- 测试状态: ✅ 通过 / ❌ 失败（修复 N 轮后通过）
- 图片转正: ✅ 已转正 N 张
- 知识库更新: app_map.json 页面状态 + AW方法指南已登记
```

## 每个 Phase 结束时必须做的事（分步模式）

1. **向用户汇报**当前阶段的产出和结果
2. **确认**是否继续下一个 Phase
3. **记录**本阶段产出物的位置和状态
