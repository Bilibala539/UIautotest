# 测试套件管理计划(草案,待核对后执行)

> 状态:设计稿。对齐禅道 ZTF 开源自动化测试模型,结合平台现有 case_defs / pipeline_jobs / 设备池 / 包管理能力。
> 参考:[ZTF 框架介绍](https://www.zentao.net/book/zentaopmshelp/ztf-282.html)、[ZTF 详解](https://www.zentao.net/book/zentaopmshelp/ztf-detail-283.html)、[ZTF GitHub](https://github.com/easysoft/ztf)

## 1. 要解决的问题

现状:自动化用例(case_defs, case_type=auto)只是静态清单,和执行链路(pipeline_jobs/设备池)没有直接关系。需要:

- 自动化用例 ↔ 测试套件(用例的集合,如"冒烟套件""登录回归套件")双向关联
- 套件可以一键触发自动化执行(平台调度:脚本用例 + 测试机资源 + 账号资源)
- 套件执行结果落执行会话(runs),失败可建单(已有链路)
- 后续流水线:开发合入出包后自动跑指定套件;夜间任务按套件跑全量回归

## 2. 借鉴禅道 ZTF 的模型

| ZTF 概念 | 本平台对应 |
|---|---|
| 脚本头部 `#tcId=用例ID` 注释,脚本↔禅道用例关联 | driver YAML 用例文件 ↔ case_defs auto 行(已通过 sync_cases.py 挂 linked_case_id / 编号后缀匹配实现,等价能力) |
| `ztf run ./ -testtask 15` 按测试单执行 | 套件执行 = 触发 pipeline_job(source=suite, suite_id=xx),agent 按套件内用例聚合 pytest 目标 |
| 执行结果回写测试单用例列表 | 执行结果回写 runs/cases(已上报),未来可扩展回写禅道测试单 |

差异说明:ZTF 用注释声明关联,我们是 YAML 结构化数据,关联更可靠;ZTF 的"测试单(testtask)"是一次执行任务的集合,我们的对应物是"套件的某次执行"(run),不单独建 testtask 表。

## 3. 数据模型

新增两张表(server.py,与 case_defs 同层):

```sql
CREATE TABLE IF NOT EXISTS test_suites (
    suite_id   TEXT PRIMARY KEY,        -- 如 SUITE-SMOKE、SUITE-LOGIN-REGRESSION
    name       TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    suite_type TEXT NOT NULL DEFAULT 'regression',  -- smoke|regression|custom
    enabled    INTEGER NOT NULL DEFAULT 1,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS suite_cases (
    suite_id TEXT NOT NULL,
    case_id  TEXT NOT NULL,             -- 指向 case_defs(auto 为主,允许文字用例进套件作参考)
    seq      INTEGER NOT NULL DEFAULT 0,-- 执行顺序
    enabled  INTEGER NOT NULL DEFAULT 1,
    PRIMARY KEY (suite_id, case_id)
);
```

- 装饰视图:case_defs 列表行带 `suites[]`(该用例属于哪些套件);套件详情带 `cases[]`(含用例状态/最近结果)
- pipeline_jobs 加列 `suite_id TEXT DEFAULT ''`(source=suite 时填写;apk/webhook/nightly 触发也可带套件)

## 4. 套件执行链路(核心)

```
页面点"执行套件" / API 触发 / 夜间任务 / 新包自动冒烟
        │
        ▼
create_pipeline_job(source='suite', suite_id=..., apk_id=?)
        │                          (状态机沿用 pending→running→succeeded/failed/env_blocked/error)
        ▼
pipeline_agent.py claim 后:
  1. 读套件内 enabled=1 的 auto 用例 → 按 file_path 去重聚合出 pytest 目标清单
     (如 knowledge/swan/cases/driver/login/*.yaml);可加 --k 过滤
  2. 设备池公平领取(已有:最久未用优先,503 无设备则 env_blocked)
  3. 账号资源:沿用测试数据规范(data_label=TEST-SYNTHETIC),套件级可配置账号池(暂用现有账号约定,P3 再建账号资源表)
  4. pytest 执行 → 上报 runs/cases(run 记 suite_id,页面可按套件过滤)
        │
        ▼
失败用例 → 证据留存 → 禅道建单(人工确认,已有链路)
```

## 5. 页面设计

- **用例管理页**:用例行"所属套件"展示(徽章);抽屉里可勾选加入/移出套件
- **新增"测试套件"页**(导航第 4 个 tab):套件列表(名称/类型/用例数/最近一次执行结果/操作),套件详情抽屉内勾选用例(支持按模块筛选)、「执行」按钮、执行历史(runs 按 suite_id 过滤)
- **执行会话页**:run 增加"套件"徽章

## 6. 流水线联动(后面接上)

1. **新包自动冒烟**:开发合入 → 出包(register_apk 登记)→ 自动 create_pipeline_job(source=apk, suite_id=冒烟套件)——与出包自动化的 watcher/webhook 方案直接衔接
2. **夜间全量回归**:nightly_trigger.py(已有,01:33)改为按"全量回归套件"触发,替代现在按目录的粗粒度方式
3. **禅道测试单回写(P4 可选)**:仿 ZTF -testtask,执行完成后把 run 结果回写禅道测试单(需要禅道 testtask API 权限,单独立项评估)

## 7. 分期实施
