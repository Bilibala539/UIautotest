# 监控 业务档案

> 更新:2026-09-21(后端交付,前端待 swan-designer 设计稿) / 依据:.166重装部署计划 v3 §7.5(docs/.166重装部署计划.md)
> 涉及文件:`dashboard/server.py`(下称 server,独立 section)、`dashboard/page.html`(下称 page,待开发)

## 1. 模块一句话职责
平台"机器监控"页签:经 server 只读代理 167 本机 Prometheus(127.0.0.1:9090),展示 167/176 两台机 CPU/内存/磁盘/网络/负载实时值与近 15 分钟走势;采集侧(Node Exporter/Prometheus/Grafana)归部署计划 §7.5 与主会话,本模块只做展示层。

## 2. 部署拓扑(硬约束)
- **dashboard 与 Prometheus 同机部署在 167**(v3 重建后 dashboard 迁 167,systemd uiautotest-dashboard.service);9090/9100 均**仅本机监听**,ufw 不放行,平台代理走 localhost。
- Node Exporter:167+176 各一,端口 9100;**167 的 scrape target 是 127.0.0.1:9100**(非局域网 IP!),176 是 192.168.12.176:9100——instance 标签精确值见 `tools/provision/monitoring-infra.md`。
- Grafana :3000 是独立深度大盘,与平台页签互不替代。

## 3. 数据流与 API 路由(均在 server,独立 section)
数据流:page(5-10s 轮询) → /api/metrics/* → server 拼 PromQL(白名单模板) → Prometheus /api/v1/query|query_range → 解析回 JSON。**无任意 query 透传**:前端只传 host 键,PromQL 全部服务端拼装。

| 方法+路径 | 用途 | 降级行为 |
|---|---|---|
| GET /api/metrics/hosts | 主机清单 [{host,instance}] | 不依赖 Prometheus,恒可用 |
| GET /api/metrics/summary?host=167 | 单机五类指标当前值+up 标志 | Prometheus 不可达→503 `{"error":"监控组件未就绪","detail":...}` |
| GET /api/metrics/history?host=167 | 近 15min 走势(30s 步长,约 30 点) | 同上 |

- host 不在白名单/缺失 → 400 `host 参数必填且必须是 167/176 之一`(白名单 METRICS_HOSTS,可 METRICS_HOSTS 环境变量 JSON 覆盖;PROMETHEUS_URL 环境变量可覆盖代理地址)。
- **两级降级**:Prometheus 整体不可达→503(整页提示"监控组件未就绪");Prometheus 在但该机 exporter 失联→`up=false`+指标 null(单机降级态,前端区分显示)。

## 4. PromQL 模板(server 独立 section 内,instance 精确匹配无注入面)
| kind | PromQL | 返回口径 |
|---|---|---|
| cpu | 100-avg(rate(node_cpu_seconds_total{instance=...,mode="idle"}[5m]))*100 | %占用 |
| mem | (1-MemAvailable/MemTotal)*100 | %占用(非"可用",与参考公式换算差异见代码注释) |
| disk | (1-filesystem_avail/size)*100,mountpoint="/",fstype!~tmpfs/overlay | /分区 %占用 |
| net_rx/tx | sum(rate(node_network_{receive,transmit}_bytes_total{...,device!="lo"}[5m])) | 字节/秒(单位换算归前端/设计稿) |
| load | node_load1 | 原值 |

summary 响应:`{host,instance,up,metrics:{cpu,mem,disk,net:{rx_bps,tx_bps},load},timestamp}`;history 响应:`{host,instance,window_seconds:900,step_seconds:30,metrics:{cpu,mem,disk,net_rx,net_tx,load:[[unix_ts,val],...]}}`。缺指标/无数据→null/空数组(前端显示 '-',不算故障)。

## 5. 行号锚点(server)
- 独立 section:常量+`_metrics_promql`/`_prom_api`/`_prom_instant`/`_prom_matrix`/`metrics_host_list`/`metrics_summary`/`metrics_history`,起于注释锚 `==== 机器监控:Prometheus 只读代理 ====`(DASHBOARD_HTML 之前),至 `==== 机器监控 section 结束 ====`。
- 路由:do_GET 内 `==== 机器监控(部署计划 v3 §7.5) ====` 注释锚,位于 404 兜底 `not found` 之前。
- 异常类:MetricsBadRequest(→400)/MetricsUnavailable(→503);_prom_api 把 URLError/TimeoutError/OSError/JSON 异常一律归一为 MetricsUnavailable。

## 7. 业务规则与坑
| # | 规则/坑 |
|---|---|
| 1 | **instance 标签陷阱**:167 是 127.0.0.1:9100 不是 192.168.12.167:9100——改 scrape 配置时必须同步 METRICS_HOSTS(或其环境变量) |
| 2 | Prometheus 仅 167 本机:9090,本模块冒烟用 PROMETHEUS_URL 环境变量指向 mock;**不许**把 9090 加 ufw 放行 |
| 3 | 5m rate 窗口:启动机 <5min 时 cpu/net 可能空→null,是正常现象不是故障 |
| 4 | 内存口径=占用率百分比(参考公式给的是可用比);net 单位 B/s,换算 Mbps/B/s 由设计稿定 |
| 5 | 本模块与 Grafana 无耦合;§7.5 后续若 Grafana 嵌入 iframe 另议 |
| 6 | 无鉴权变更,与现有页面同模式(页面本身无鉴权) |
