融合怎么工作:用例的旅程

分享包的 YAML 用例本身跑不了(没有元素信息);翻译管线把它变成真机可执行的 pytest。

  1. 读用例 — cases/login/*.yaml(分享包)定义每条用例的步骤与预期,并给出元素 key 清单(ui_contract)。
  2. 对知识 — 步骤引用的页面/元素到 pages/ 核对;缺页缺元素 → 派探索 agent 补(这正是下次探索的任务单来源)。
  3. 封装 AW — 步骤抽象成 SwanBusiness 业务方法(本地),用例只调方法、不碰元素细节。
  4. 产 pytest — 按 G1-G5 门禁生成测试文件(融合);每条用例的可执行度评级登记进 TRANSLATION-NOTES。
  5. 真机跑 + 回写 — 结果回写 BUG 库 / session-state / 看板,新发现反馈给源头机器。

纪律沿用自分享包宪法

  1. 证据纪律 — 没有截图/日志证据的"通过"不成立;环境阻塞记 BLOCKED,不算业务失败。
  2. 三类停机 — BUG 定级争议、测试范围取舍、不可逆动作(提单/删知识库),必须停下问人。
  3. 危险操作黑名单 — 注销账号、添加设备、平台授权、设备同步/删除等 key 在封装层标注 ⛔,用例禁止触碰。
  4. BUG 查重 — 报新 BUG 前先查 bugs/(6 份已知 + 模式库 P-001~P-004);负向用例设计先看模式库。
