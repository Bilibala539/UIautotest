# 执行与证据 业务档案

> Swan 测试平台 · 执行会话/用例历史/证据/禅道建单 | 更新 2026-09-22(行号实读校准) | 供 teammate 会话冷启动恢复业务上下文

## 1. 一句话职责
记录每次自动化执行(run)与每条用例结果(case),提供会话列表/详情与用例历史查询、失败证据留存策略,并把失败用例半自动提单到禅道(人工确认后才提交)。

## 2. 数据表(DDL: dashboard/server.py:446-489)
| 表 | 字段 | 说明 |
|---|---|---|
| runs | run_id PK, platform, status(默认 running), app_version, device, jenkins_build, started_at, ended_at, duration_seconds, total/passed/failed/skipped/error_cases, metadata_json, zentao_task_id(462); apk_id/zentao_task_id 老库轻量迁移补列(server.py:484-489) | 一次执行会话 |
| cases | (run_id, case_id) 联合 PK, name, platform, status, started_at/ended_at, duration_seconds, log, error, artifacts_json; FK→runs ON DELETE CASCADE(464-478) | 一条用例结果,case_id=pytest nodeid |
| 索引 | idx_runs_started_at / idx_cases_run_id / idx_cases_case_id(server.py:479-481) | |

状态机:
- runs: 创建即 running(create_run 665,INSERT 默认 'running')→ complete_run 归一定终态(server.py:764-768):上报 passed 但存在 failed/error 强制改 failed;非法值按有无失败兜底。
- **孤儿收尾**(2026-09-20 加,_sweep_orphan_runs:782):run 卡 running 而关联 pipeline job 已终态(succeeded/failed/env_blocked/error,含 reaped 抢回)→ get_run/list_runs 查询路径惰性代管收尾(幂等,get_run 内 1283 调用)。关联键=执行 agent 的 run_id 约定 pipe-{job_id}(pipeline_agent.py:124)前缀反查,不依赖 job 侧;ended_at 取 job.finished_at,状态口径:job succeeded 且有用例→按 cases 聚合(对齐 complete_run),失败/抢回/无用例→error;reaped 等写 metadata_json.orphan_swept(job_id/job_status/reaped/reason/swept_at),日志 logs/runs_sweeper.log。
- cases: normalize_status 别名归一(server.py:82-95):pass/success→passed、fail→failed、skip→skipped、broken→error,未知→error。
- pass_rate 不落库,serialize_run 现算(server.py:1260-1262)。

## 5. 脚本与上报链路
- pytest 插件 dashboard/pytest_plugin.py(经根 conftest.py:20 `pytest_plugins` 全局加载):
  - pytest_configure→start()(28):POST /api/runs 建"running"会话;run_id 取 env DASHBOARD_RUN_ID 否则 `pytest-时间戳-uuid8`(22);字段取 env PLATFORM/APP_VERSION/SWAN_APK_ID(42)/ANDROID_DEVICE_SERIAL/BUILD_TAG;web 平台也上报。
  - logreport:仅 call 阶段记结果(setup 只记起始时刻);log/error 各截 20000 字;artifacts 存 jenkins_build/apk_id(76)/evidence_dir;POST /api/runs/{id}/cases。
  - sessionfinish→finish()(83):任一 failed/error 则会话 failed,POST complete。
  - DASHBOARD_URL 未设则全链路静默跳过、上报失败不抛错(dashboard/client.py)。
- scripts/evidence_cleanup.py(本机计划任务 EvidenceCleanup 每日跑):失败会话(或目录含 FAIL_*.png,67)证据**永久保留**;passed/skipped/running 超 7 天删;孤儿(平台 404/不可达)超 30 天宽限删;空目录随时删;平台不可达时保守不误删;支持 --dry-run(93)。

## 6. 关键业务规则与坑
- **提单不可逆(硬纪律)**:/api/zentao/create 缺 confirm 字段直接 400;页面必须经 bug-modal 人工确认(页面侧 confirm:true 在 bug-submit 761);任何脚本/自动化禁止绕过弹窗直接 POST create。环境缺陷(网关不通/设备掉线)不建业务 bug 单(zentao_client.py:13-14)。
- **孤儿收尾关联契约**:runs 侧靠 run_id `pipe-{job_id}` 前缀反查 pipeline job——这是与 pipeline_agent 的隐式契约,若执行 agent 改 run_id 约定须同步改 _sweep_orphan_runs(两侧都要动)。手工 pytest 会话(pytest-* 前缀)不受影响。
- **禅道测试单回写(M6,2026-09-20)**:REST v1 无用例级回写端点(/testruns、/testtasks/{id}/testruns 均 404),结果以汇总 HTML 写进 testtask desc。runs.zentao_task_id 列(DDL 462+PRAGMA 迁移 488-489)存单号:空→POST /testtasks 建单并回存,非空→PUT /testtasks/{id} 更新 desc(重复点击=更新同一单,幂等)。project/product 读 env ZENTAO_PROJECT_ID/ZENTAO_PRODUCT_ID(.env.local),未配置 400;running 409(RunNotFinalizedError);禅道错 502。build 取 run.jenkins_build 否则 "trunk"——禅道 build 若要求产品内合法 build id,trunk 兜底是否被 22.1 接受待真实回写验证。desc 用例清单超 50 条截断。zentao_client 新增 create_testtask(107)/update_testtask(124)。**人工确认纪律:仅页面"回写禅道测试单"按钮触发,禁止任何自动回写**。
- 禅道凭据只在部署机 .env.local(ZENTAO_URL/ACCOUNT/PASSWORD/PROJECT_ID/PRODUCT_ID),不进 git;URL http://8.129.106.82:9000/zentao,产品 7=Swan Audio Flutter;REST v1 tokens→products→bugs,create_bug 默认 keywords="自动化"、type=codeerror(zentao_client.py:84-101)。
- 建单链路:失败用例→openBugDraft(736;先查 /api/zentao/config 缓存 zentaoConfigured,未配置 alert 拦截 737-740)→POST draft(标题 `[Swan][模块] 用例名 自动化失败(run_id)`,steps 含复现步骤+日志尾 1500 字+证据截图目录,2445-2480)→弹窗人工修改→POST create(confirm:true);产品 ID 记 localStorage('bug-product')(748/758)。
- **快照规则**:cases 行是执行时快照(case_id=当时 pytest nodeid;artifacts_json 存当时的 apk_id/jenkins_build/evidence_dir);case_defs 后续改名/编辑**不回写**历史记录;查历史时包/设备从所属 run 行 JOIN 取(get_case_history 1398-1413)。runs 是 upsert,同 run_id 重跑会覆盖 apk_id 等并重置 running(680-686)。
- /api/cases/search 空 q 返回全部是明确需求(未搜索先展示全部,server.py:1415-1418)。
- 自测纪律:禅道改动用 monkeypatch 拦 `zentao_client._request`(43)验证 payload,绝不真建单;本地临时端口起 server 冒烟。

## 7. 模块边界
- 流水线执行(pipeline_agent/设备池):执行 agent 跑 pytest,run/case 记录由本模块 pytest_plugin 上报产生;pipeline_jobs 状态流转归其模块,结果展示落本模块页面。
- 包管理:runs.apk_id↔apks 表关联;page-apks 原"查看执行"按钮已移除,包体筛选下拉仍由 /api/apks 填充(本模块 loadApks)。
- 用例管理(case_defs):cases.case_id 与 case_defs.case_id 同键空间(nodeid);历史页↔用例定义页互跳;改定义不回写历史(见快照规则)。
- 套件/流水线调度:套件执行的 run 走同一上报链路,但 runs 无 suite_id 字段,套件维度历史暂查不了。
