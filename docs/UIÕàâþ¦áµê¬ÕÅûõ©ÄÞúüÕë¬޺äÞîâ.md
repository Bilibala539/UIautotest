> 截取的图片用于 `image_exists` / `click_image` 等模板匹配操作，图片质量直接影响测试稳定性。

## 2. 截取 vs OCR 的决策

并非所有 UI 元素都需要截取图片，有些用 OCR 文字识别更合适。以下是决策参考：

| ✅ 适合截取图片（click_image / image_exists） | ✅ 适合 OCR 定位（click_text / find_text_by_ocr） |
|:---|:---|
| 图标按钮（无文字或文字不稳定） | 纯文字标签（"确定"、"取消"、"发送"） |
| 状态标识（勾选框、开关、高亮 Tab） | 页面标题文字 |
| 导航元素（Tab 高亮/灰色状态区分） | 动态内容（用户名、时间） |
| 自定义控件（滑块、进度条） | 固定文案（"搜索"、"设置"） |
| 有颜色/状态变化的元素 | 列表项文字 |

> **原则：能用 OCR 稳定定位的文字元素，就不截图；图标和状态类元素，必须截图。**

## 3. 截取五大核心原则

### 3.1 分辨率一致

截图来源的模拟器窗口**必须是 540×960**，与测试用例执行环境一致。

```bash
# 设置模拟器窗口分辨率
D:\MuMuPlayer\nx_main\MuMuManager.exe control -v {instance_id} layout_window -sw 540 -sh 960
```

### 3.2 紧贴边缘

截取区域紧贴元素内容边缘，上下左右各留 **1~2px**，不留大片空白：

```
❌ 留白太多（匹配不稳定）       ✅ 紧贴边缘（匹配准确）
┌──────────────────┐           ┌──────────┐
│                  │           │ 我的收藏  │
│    我的收藏       │           └──────────┘
│                  │
└──────────────────┘
```

### 3.3 单元素原则

每张图片只包含 **1 个** UI 元素，不混入相邻元素。

### 3.4 宁小勿大

不确定边界时，宁可截取更小的核心区域，避免引入干扰。

### 3.5 静态优先

优先截取不会变化的静态内容（固定图标、固定文案），避免截取动态变化的内容。

## 4. 动态元素规避规则

截取时**严禁**将以下动态内容截入图片：

| 动态元素 | 常见位置 | 规避方法 |
|---------|---------|---------|
| 🔴 **红色未读角标/红点** | 图标右上角 | 检测红色像素底边，从其下方截取 |
| 🕐 时间戳 | 列表项右侧 | 不截取包含时间的区域 |
| 🟢 在线状态点 | 头像右下角 | 避开头像区域 |
| 👤 用户头像 | 各处 | 只取文字或固定图标 |
| 💬 消息列表内容 | 页面中部 | 不截取消息区域 |
| ⌨️ 输入框内容 | 搜索栏/输入区 | 不截取输入内容区域 |
| 📋 联系人列表项 | 通讯录中部 | 不同账号不同，不截取 |

### 红色角标检测与规避

红色角标像素满足以下条件：

```python
# 红色角��像素判断
def is_red_badge_pixel(r, g, b):
    return int(r) > 200 and int(g) < 160 and int(b) < 170 and int(r) - int(g) > 40
```

截取图标时的规避策略：

```
图标截取示意图（避开右上角角标）：
┌─────────────┐
│    [角标]   │  ← 不要截到这里
│  ┌─────┐    │
│  │图标 │    │  ← 只截取这个区域
│  │主体 │    │
│  └─────┘    │
│   文字      │
└─────────────┘
```

截取后验证是否残留角标像素：

```python
import numpy as np

r, g, b = cropped[:,:,0].astype(int), cropped[:,:,1].astype(int), cropped[:,:,2].astype(int)
red_mask = (r > 200) & (g < 160) & (b < 170) & (r - g > 40)
assert red_mask.sum() == 0, f"截取结果中仍有 {red_mask.sum()} 个红色角标像素！"
```

## 5. 窗口边缘阴影规避

MuMu 模拟器截图在窗口**四角和边缘**存在灰色渐变阴影，必须排除。

### 阴影分布（540×960 分辨率）

| 阴影位置 | 坐标范围 | 表现 |
|---------|---------|------|
| 顶部状态栏 | y < 40 | 系统状态栏 |
| 左上角/右上角圆角 | x<40 或 x>500, y=845~862 | 灰色渐变 |
| 底部边缘 | y > 935, 全宽 | 整行灰色渐变 |

### 页面安全区域示意图

```
y=0   ┌───────────────────────┐  ← 系统状态栏（⚠️ 避开）
      │  ░░░ 状态栏 ░░░░░░░░  │
y~40  ├───────────────────────┤
      │                       │
      │     页面主体内容       │  ← ✅ 安全区域
      │                       │
y~840 ├───────────────────────┤  ← 导航分割线
      │ ▓▓              ▓▓   │  ← ⚠️ 角落阴影
y~860 │  ┌──┐  ┌──┐  ┌──┐   │  ← ✅ 真实图标开始
      │  │图│  │图│  │图│   │
y~932 ├───────────────────────┤  ← ✅ 真实内容结束
      │ ░░░░░░░░░░░░░░░░░░░  │  ← ⚠️ 底部窗口阴影（避开）
y=960 └───────────────────────┘
```

**底部导航栏安全截取区域：y = 860 ~ 932**

**区分阴影 vs 真实内容**：阴影像素 R ≈ G ≈ B（灰色），真实内容有明显色彩差异或足够深。

## 6. 命名规范

### 6.1 文件命名

**格式**：`{页面名称}-{元素名称}.png` 或 `{页面名称}-{元素名称}-{状态}.png`

**连接符**：短横线 `-`

| 示例文件名 | 说明 |
|-----------|------|
| `登录页-登录按钮.png` | 页面 + 元素 |
| `消息tab页-导航栏消息蓝色高亮.png` | 页面 + 元素 + 状态 |
| `侧边栏-我的收藏.png` | 页面 + 元素 |
| `通讯录页-搜索按钮.png` | 页面 + 元素 |

### 6.2 常量命名

**格式**：`UPPER_SNAKE_CASE`（页面英文缩写 + 元素英文缩写）

| 文件名 | 常量名 |
|--------|--------|
| `登录页-登录按钮.png` | `LOGIN_ENTER` |
| `消息tab页-导航栏消息蓝色高亮.png` | `MESSAGE_TAB_BLUE` |
| `侧边栏-设置.png` | `SIDEBAR_SETTINGS` |
| `通讯录页-搜索按钮.png` | `CONTACTS_SEARCH_BUTTON` |

### 6.3 页面前缀对照表

| 页面名称 | 常量前缀 |
|---------|---------|
| 登录页 | `LOGIN_` |
| 桌面 | `HOME_` |
| 消息tab页 | `MESSAGE_TAB_` |
| 侧边栏 | `SIDEBAR_` |
| 设置页 | `SETTINGS_` |
| 通讯录页 | `CONTACTS_` |
| 群聊页 | `GROUP_CHAT_` |
| 群设置页 | `GROUP_SETTINGS_` |

### 6.4 注册到映射文件

在 `image/image_name_mapping.py` 末尾追加，按功能区域分组并用注释分隔：

```python
# === 新功能区域 ===
# 草稿（暂存目录，待验证）
NEW_ELEMENT = os.path.join(test_path, "页面名称-元素名称.png")

# 转正后改为：
NEW_ELEMENT = os.path.join(path, "页面名称-元素名称.png")
```

## 7. 截取操作完整流程

```
┌──────────────────────────────────────────────────────────┐
│  步骤 1：获取截图                                         │
│  通过 ADB 截图获取当前页面（确保模拟器分辨率 540×960）       │
└──────────────────────┬───────────────────────────────────┘
                       ▼
┌──────────────────────────────────────────────────────────┐
│  步骤 2：定位元素坐标                                      │
│  分析截图，确定目标元素的边界框 (x1, y1, x2, y2)            │
│  紧贴边缘、避开动态元素和阴影                                │
└──────────────────────┬───────────────────────────────────┘
                       ▼
┌──────────────────────────────────────────────────────────┐
│  步骤 3：裁剪并保存到暂存目录                               │
│  img.crop((x1, y1, x2, y2))                              │
│  保存到 image_ai/页面名称-元素名称.png                      │
└──────────────────────┬───────────────────────────────────┘
                       ▼
┌──────────────────────────────────────────────────────────┐
│  步骤 4：在 image_name_mapping.py 中用 test_path 注册常量  │
└──────────────────────┬───────────────────────────────────┘
                       ▼
┌──────────────────────────────────────────────────────────┐
│  步骤 5：运行测试验证匹配效果                               │
└──────────┬───────────────────────────────┬───────────────┘
           ▼                               ▼
┌──────────────────────┐    ┌──────────────────────────────┐
│ ✅ 测试通过            │    │ ❌ 测试失败                    │
│ 移动图片到 image/     │    │ 留在 image_ai/ 重新截取       │
│ 映射改为 path（转正）  │    │ 不污染正式目录                │
└──────────────────────┘    └──────────────────────────────┘
```

### 代码示例

```python
from PIL import Image

# 打开截图
img = Image.open(r"E:\UIAutotest\explorer_output\screenshots\page_screenshot.png")

# 裁剪元素（紧贴边缘，留 1~2px）
```

## 8. 质量检查清单

每次截取元素前后，**必须**确认以下 8 项检查：

### 截取前检查（4 项）

| # | 检查项 | 标准 | 示例 |
|---|--------|------|------|
| 1 | 坐标顺序正确 | x1 < x2, y1 < y2 | `(100, 200, 150, 250)` ✅ |
| 2 | 坐标在图片范围内 | 不超出 540×960 边界 | x2 ≤ 540, y2 ≤ 960 |
| 3 | 最小尺寸 | 至少 10×10 像素 | 宽高均 ≥ 10 |
| 4 | 命名含页面前缀 | 如 `登录页-`、`通讯录页-` | `消息tab页-xxx.png` ✅ |

### 截取后检查（4 项）

| # | 检查项 | 标准 | 说明 |
|---|--------|------|------|
| 5 | 图片不是空白 | 灰度标准差 > 5 | 有足够的对比度 |
| 6 | 图片不是全黑/全白 | 灰度均值在 5~250 | 非纯色 |
| 7 | 未截入动态元素 | 不含角标、时间戳等 | 红色像素数 = 0 |
| 8 | 未截入窗口阴影 | 不含边缘灰色渐变 | 检查四角像素 |

### 检查代码参考

```python
import cv2
import numpy as np

def validate_cropped_image(img_path):
    """截取后质量检查"""
    img = cv2.imread(img_path)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    errors = []

    # 检查空白
    if np.std(gray) < 5:
        errors.append("❌ 图片可能为空白（灰度标准差 < 5）")

    # 检查全黑
    if np.mean(gray) < 5:
        errors.append("❌ 图片全黑（灰度均值 < 5）")

    # 检查全白
    if np.mean(gray) > 250:
        errors.append("❌ 图片全白（灰度均值 > 250）")

    # 检查红色角标残留
    r, g, b = img[:,:,2].astype(int), img[:,:,1].astype(int), img[:,:,0].astype(int)
    red_mask = (r > 200) & (g < 160) & (b < 170) & (r - g > 40)
    if red_mask.sum() > 0:
        errors.append(f"❌ 残留 {red_mask.sum()} 个红色角标像素")

    if not errors:
        print("✅ 质量检查全部通过")
    else:
        for e in errors:
            print(e)

    return errors
```

## 9. 暂存→验证→转正流程

```
1. 截取图片 → 保存到 image_ai/（暂存目录）
2. 在 image_name_mapping.py 中用 test_path 注册常量
3. AW 代码引用常量 → 运行 pytest 验证匹配效果
4a. ✅ 测试通过 → 移动图片到 image/，映射改为 path（转正）
4b. ❌ 测试失败 → 留在 image_ai/ 重新截取，不污染正式目录
```

**为什么要分两个目录？**

- `image/` 是生产目录，只存放经过验证的可靠图片
- `image_ai/` 是草稿目录，新截取的图片在此验证
- 这样确保失败的截取不会影响已有测试用例的稳定性
